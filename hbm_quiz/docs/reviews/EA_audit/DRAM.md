# EA 독립 감사 — DRAM (W2 완료분)

- 감사: EA · 2026-11-21 · 대상: `data/09_DRAM.json` 198문항(B64/I70/A64), 보고서 `docs/reviews/DRAM.md`, 원본 `scratchpad/w2/DRAM/orig_09_DRAM.json`
- 자동 검사: 감사 시점 E 0 / W 0 (게이트 통과). 표준 수치는 FACT W2-08~ 검증이 진행 중이라 그 판정이 나오면 해당 문항만 추가 확인.

## 판정 요약: **합격 (수정 3건 후 확정)**
타이밍(tFAW 상한)·refresh 점유율·Little 법칙·ECC 확률·bank 충돌(생일 문제)·memory-bound 토큰 속도 문항이 정확하고, 설정값이 실제 제품과 맞습니다(DDR4 8 Gb tRFC 350 ns, HBM4 pseudo channel 32 GB/s, B200 급 HBM3E 8 스택 8 TB/s). F08·F09 는 반영되었습니다 — 비실재 구성은 오답으로만 등장하고 그렇다고 해설이 밝힘(B-0083).

## 2. 수정 지시 (DRAM 에이전트)
| # | id | 문제 | 지시 |
|---|---|---|---|
| 1 | DRAM-A-9021 | ② 60 개를 "채널 수 32 와 혼동해 다시 반으로" 라 했으나, 32 채널로 나누면 7,680 ÷ 32 = **240** 개. 60 은 ÷ 128 로만 나옴 — 재현되지 않는 오답 | ② 를 "약 240 개(pseudo channel 64 대신 채널 32 로 나눔)" 로 교체 |
| 2 | DRAM-A-9044 | "최하단 온도" 로 refresh(2배)를 판정하나 어느 die(base 인지 최하단 core 인지)인지 불명 — base die 에는 셀이 없음(THERM 감사와 같은 문제). 또 "단마다 0.05 °C/W × 단수" 가 간극 N 개 규약과 맞는지 지문에 없음 | 지문을 "최하단 core die" 로 명시하고 열저항이 지나는 간극 수를 규약대로(최하단 core 까지 N−1 또는 base 까지 N) 적어 재계산 |
| 3 | DRAM-A-0083 | 경로 B "4,096 bit" 는 실재 HBM 구성이 아님(F09) — 지문이 '스택' 이라 HBM 으로 읽힘 | 지문에 "가상의 4,096 bit 인터페이스(계산 연습용)" 를 명시(STANDARDS 2.2) |

참고: B-0045 ① "8 을 % 로 읽은 값" 은 약한 오답 — Phase 2 전에 여유가 있으면 "(72 − 64) ÷ 64 를 72 로 나눔" 같은 재현형으로.

## 3. 삭제 표본 (12건) — **개념 손실 없음**
비실재 구성 가족(I-0028 512 bit · 32채널, I-0043 256 bit, A-0016), 비실재 속도 대역폭(A-0006 1,024 × 12 Gb/s, B-0020 2,048 × 9.6 — F08/F09), ECC 오버헤드 가족(A-0026·A-0028·B-0047 — B-0045 대표), 보존 시간 반감 가족(I-0090·I-0091·A-0054 105 °C — F45 105 °C 근거 없음, A-9009 가 10 °C 반감 vs Ea 모델로 재구성), 일반론(B-0160). 삭제가 기준서와 FACT 판정에 정확히 맞습니다.

## 4. 커버리지·보강 권고
- 타이밍·refresh·RAS·ECC·SI·셀 물리·작업 부하(memory-bound)가 고르게 있음. 고급 32 %.
- **보강 권고(다음 차수, 고급 2–3)**: ① HBM 고유 — TSV 경유 채널의 die 위치별 tDQSS/skew 차이로 최상단 die 에서만 실패하는 데이터 해석 1(A-9020 IR 과 다른 기구), ② pseudo channel 모드에서 bank group 제약(tCCD_L/S)과 실효 대역폭 1, ③ FACT W2-08~ 결과가 나오면 표준 타이밍 값을 쓰는 문항 재확인.
