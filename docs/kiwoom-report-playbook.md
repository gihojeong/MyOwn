# 키움 수집기 사용 지침 — KOSPI 리포트 예약작업용

예약작업(Routine) 프롬프트가 이 문서를 가리킨다. 지침을 여기에 두는 이유는, 트리거
프롬프트를 세 개나 고치지 않고도 수집 항목과 주의사항을 바꿀 수 있게 하기 위해서다.

## 실행

예약작업 세션에는 저장소가 붙지 않으므로(`folders: []`) 스크립트를 URL로 받는다.
앱키는 환경변수(`APP_KEY` / `APP_SECRET` / `KIWOOM_MODE`)로 이미 주입돼 있다.
건드리지도, 출력하지도 마라. `ECOS_API_KEY`(한국은행)는 선택이며, 없으면 공개 sample
키로 자동 동작한다.

```bash
curl -fsSL -o kiwoom_collect.py \
  https://raw.githubusercontent.com/gihojeong/MyOwn/master/scripts/kiwoom_collect.py

# 마감 리포트(89건) / 개장 전 브리핑(80건) / 주간 리뷰(69건)
python3 kiwoom_collect.py --preset close     --date <오늘YYYYMMDD>       --pause 0.3 --out kiwoom.json
python3 kiwoom_collect.py --preset premarket --date <직전거래일YYYYMMDD> --pause 0.3 --out kiwoom.json
python3 kiwoom_collect.py --preset weekly    --date <지난주금요일YYYYMMDD> --pause 0.3 --out kiwoom.json
```

순차 호출이라 6~10분 걸린다. **백그라운드로 던지고 그동안 Drive 읽기와 요인 분석용 웹
검색을 병렬로 진행하라.**

★결과 JSON은 3MB가 넘는다(2026-09-04 close 실측 3.24MB). **Read 도구로 통째로 읽지 마라 —
컨텍스트가 날아간다.** 반드시 python으로 필요한 키만 꺼내 써라. 용량 상위는 `investor_after_close`
406KB · `investor_intraday_외국인` 315KB · `candle_daily_*` 각 130KB다. 일봉은 600행이 오지만
리포트에 쓰는 것은 앞 2~25행뿐이다.

```python
import json
d = json.load(open("kiwoom.json"))
r = d["results"]
print(d["summary"])                                  # 먼저 이것부터
kospi = r["index_kospi"]["data"]                     # 스칼라 필드만 골라 쓴다
close = r["candle_daily_삼성전자"]["data"]["stk_dt_pole_chart_qry"][0]["cur_prc"]
```

`summary.failed`가 빈 배열이면 전량 성공이다. 실패 항목이 있으면 **그 항목만** 웹 경로로
보완한다. 성공한 항목을 웹에서 다시 찾지 마라 — 시간 낭비이고, 웹 수치가 API 확정치와
어긋나면 **API가 옳다**(차이는 각주로 남겨라). 수집기가 아예 안 돌면(토큰 실패·네트워크)
그 사실을 리포트 말미에 명시하고 웹 경로로 전환한다.

## KOSPI200 선물 — `krx_futures` 읽는 법 (2026-09-04 실측)

키움에 파생이 없어 한국거래소 OpenAPI에서 받는다. 결과 키는 세션·상품별로 나뉘어 있다.

| 키 | 내용 |
| --- | --- |
| `k200_regular` | 코스피200 선물 **정규장** 13행(월물·스프레드) |
| `k200_night` | 코스피200 선물 **야간장** 13행 |
| `k200_mini_regular` / `k200_mini_night` | 미니코스피200 선물 |

필드: `TDD_CLSPRC`(종가) `SETL_PRC`(정산가) `SPOT_PRC`(기초자산 지수) `ACC_OPNINT_QTY`(미결제약정)
`ACC_TRDVOL`(거래량) `ACC_TRDVAL`(거래대금) `ISU_NM`(예: "코스피200 F 202609 (주간)").
**전부 문자열이고 미거래 월물은 빈 문자열로 온다 — `float()` 직전에 반드시 확인하라.**

**베이시스**는 별도 항목이 아니다. 같은 행의 `TDD_CLSPRC − SPOT_PRC`로 구하라.
2026-09-04 근월물: 1052.50 − 1051.52 = **+0.98 (콘탱고)**. `SPOT_PRC`가 `index_kospi200.cur_prc`와
정확히 일치하므로 이 자체가 교차검증이 된다.

### 야간장은 정규장에 선행한다 — 절대 합산하지 마라

같은 `BAS_DD`에 정규·야간이 **각각 독립 집계**로 온다. 2026-09-04 근월물(A0169000) 실측:

```
야간  종가 1049.05  전일대비 +19.05  →  기준 전일종가 1030.00   거래량  26,252  미결제 149,439
정규  종가 1052.50  전일대비 +22.50  →  기준 전일종가 1030.00   거래량 103,413  미결제 147,443
```

둘 다 같은 전일 종가를 기준으로 삼는다 = **야간은 그날 정규장에 앞서는 세션**(전일 저녁~당일 새벽)이다.
합산하면 거래량이 이중계상되고, `SETL_PRC`는 야간에 빈 값이다.
**확정 일별시세로 쓸 때는 `k200_regular`만, 밤사이 갭 신호로 쓸 때는 `k200_night`만 읽어라.**

개장 전 회차에는 `krx_futures_today`(당일자)가 추가로 들어온다. 여기 `k200_night`가 있으면
**그것이 곧 밤사이 갭의 직접 관측치**다. 게시 전이면 `error`로 남으니 그때만 EWY 프리미엄으로 갈음하라.

## 옵션 — `krx_options` 읽는 법 (2026-09-04 실측 17,092행)

**응답은 집계된 상태로 온다.** 원시 행이 17,092개라 그대로 실으면 결과 JSON을 못 쓴다.
수집기가 코스피200 근월물만 골라 행사가별로 접어 `k200_regular` / `k200_night`에 넣는다.

| 키 | 내용 |
| --- | --- |
| `pc_oi_ratio` | **풋/콜 미결제약정 비율 — 주 지표** |
| `pc_volume_ratio` | 풋/콜 거래량 비율(보조. 아래 참고) |
| `max_pain` | 만기 시 옵션 보유자 총 내재가치가 최소가 되는 행사가 |
| `call_oi` `put_oi` `call_volume` `put_volume` | 근월물 합계 |
| `strikes` | 미결제 상위 25개 행사가. 각각 `call_oi` `put_oi` `call_iv` `put_iv` `call_close` `put_close` |
| `term` | 근월물(예: 202609) |

**거래량이 아니라 미결제약정을 봐라.** 옵션 거래량 자체는 현물을 움직이지 않는다.
전달 경로는 (1) 옵션 매도자의 델타헤지 플로우 (2) 만기일 청산 (3) 지수차익거래뿐이고,
(1)의 크기를 결정하는 것은 그날 거래량이 아니라 **미결제 잔고 × 델타**다. (3)은 이미
`program_trades_kospi`의 차익 항목으로 잡고 있다.

**만기 주간에만 무겁게 쓰라.** 만기(매월 둘째 목요일)가 가까울수록 `max_pain` 부근의
핀 효과와 행사가별 미결제 집중이 실제로 지수를 붙든다. 그 밖의 날에는 `pc_oi_ratio`
하나만 포지셔닝 지표로 언급하면 충분하다.

**감마는 확정 지표로 쓰지 마라.** `call_iv`/`put_iv`(`IMP_VOLT`)가 응답에 직접 오므로
행사가별 감마 자체는 계산할 수 있다. 그러나 **딜러가 롱인지 숏인지는 데이터에 없다.**
"딜러가 콜 매도·풋 매수" 가정을 넣어야 부호가 정해지는데 그건 관측이 아니라 가정이다.
리포트에 쓸 때는 반드시 가정임을 밝히고, 확정 지표는 `pc_oi_ratio`와 `max_pain`까지로 한정하라.

### 옵션 스키마가 선물과 다른 점 (파서를 고칠 때 참고)

- **`MKT_NM`이 없다.** 세션은 `ISU_NM` 끝의 `(정규)` / `(야간)` 접미사뿐이다.
  단 "코스닥150 위클리(월) 옵션" 84행은 접미사가 없어 `IMP_VOLT`로 가른다(야간은 전부 0.00).
- **`SETL_PRC`·`SPOT_PRC`도 없다.** 기초자산 지수는 `index_kospi200`에서 가져와라.
- 콜/풋은 `RGHT_TP_NM`에 **영문 대문자** `CALL`/`PUT`.
- **행사가 전용 필드가 없다.** `ISU_NM`을 파싱해야 하고 **천단위 콤마가 들어간다**
  (`"코스피200 C 202609 1,150.0 (정규)"`).
- `PROD_NM` 5종: 코스피200 옵션 / 미니코스피200 옵션 / 코스닥150 옵션 /
  코스피200 위클리(월) 옵션 / 코스닥150 위클리(월) 옵션. **위클리는 괄호를 포함**한다.
- 야간행은 `IMP_VOLT`가 전부 `0.00`이므로 IV는 정규장에서만 유효하다.

### 키에 보이지 않는 문자가 섞이면

웹 콘솔에 키를 붙여넣을 때 제로폭 공백(U+200B)이 딸려오는 일이 있다. 2026-09-05에 실제로
발생했고, 이 경우 요청이 네트워크로 나가지도 못한다. 수집기가 읽는 즉시 털어내고 몇 글자를
지웠는지 stderr에 알린다. 경고가 보이면 환경변수 등록값 자체를 다시 붙여넣는 편이 낫다.

## 프롬프트에 남아 있는 낡은 지시 — 이 문서가 정본이다

세 트리거 프롬프트는 2026-09-05 1차 도입 시점의 문장을 그대로 담고 있다. 그날 이후
수집 범위가 넓어졌으므로, 아래 세 가지는 **프롬프트가 아니라 이 문서를 따르라.**

1. 프롬프트의 "★수집기에 없어 웹 조사가 그대로 필요한 것: KOSPI200 선물·베이시스·미결제,
   원/달러, 국고채 금리, 공매도, 시가총액·상장주식수, 해외 증시·지표.★" 목록은 낡았다.
   그중 **KOSPI200 선물·베이시스·미결제만 남았고 나머지는 전부 수집기에 들어왔다.**
   아래 "수집기에 없는 것" 절이 정본이다.
2. `[D-2]`의 "시총·상장주식수 확보 경로 1순위: stockdigging.com"은 **관심종목 8개에는
   적용하지 마라.** 그 8개는 `profile_*`에 확정치가 있다. stockdigging은 시총 상위 30 중
   나머지 종목을 채울 때만 쓴다.
3. `[A]`의 원/달러·국고채 3년/10년, `[B]`의 공매도, `[E]`의 해외 증시는 각각 `ecos_*`,
   `short_selling_*`, `us_*`로 이미 확보된다. 웹 조사를 시작하지 마라.

## ★거래소 기준은 KRX다 — NXT는 괴리 계산에만 쓴다

수급·프로그램매매·종가·순위 계열은 모두 KRX 기준(`stex_tp=1`)으로 받는다. 통합(KRX+NXT,
`stex_tp=3`)이 아니다. 이유는 둘이다.

1. **지수와 시가총액이 KRX 종가로 산출된다.** 2026-09-11 실측: 삼성전자 상장주식수
   5,846,279천주 x KRX 종가 259,500원 = 15,171,094억으로 `profile_*`의 `mac`
   15,171,093억과 맞는다. 통합 종가 262,000원으로는 맞지 않는다. 통합 수치를 쓰면
   지수 항등식과 시총 기여도 계산이 어긋난다.
2. **마감 리포트가 도는 18:05에 통합은 아직 미확정이다.** NXT 애프터마켓은 20:00까지
   거래한다. 그 시각의 통합 수치는 확정치가 아니다.

차이는 작지 않다. 2026-09-11 KOSPI 프로그램매매(ka90010, P00101) 실측 대조:

| 기준 | 차익 | 비차익 | 전체 |
| --- | --- | --- | --- |
| KRX (`stex_tp=1`, 현행) | −511억 | −17,617억 | −18,128억 |
| 통합 (`stex_tp=3`, 구버전) | −2,737억 | −20,034억 | −22,771억 |

**그래도 통합을 버리지 않는다.** `investor_after_close_all`이 ka10066을 통합으로 한 번 더
불러 두는 몫이다. 이 키의 `cur_prc`는 NXT 애프터마켓(15:40~20:00)까지 반영한 통합 최종가라,
KRX 종가와 나란히 놓으면 [C]가 요구하는 **NXT 괴리율**이 그대로 나온다. 웹에서 따로 찾지 마라 —

`investor_after_close_all.cur_prc ÷ candle_daily_*.cur_prc − 1`

2026-09-11 실측:

| 종목 | KRX 정규장 (`candle_daily_*`) | 통합 (`investor_after_close_all`) | 괴리 |
| --- | --- | --- | --- |
| 삼성전자 | 259,500 | 262,000 | +0.96% |
| SK하이닉스 | 1,812,000 | 1,832,000 | +1.10% |
| SK스퀘어 | 1,089,000 | 1,096,000 | +0.64% |
| 삼성전자우 | 193,300 | 193,300 | 0.00% |

밤사이 해외 변수에 대한 국내 투자자의 첫 반응이므로 시가 갭의 선행 신호로 읽되,
괴리 0.00%(위 삼성전자우)는 **NXT 거래가 없었다는 뜻이므로 정보량 0으로 판정하라.**

**종가·등락률·지수 기여도 계산에는 여전히 `candle_daily_*`(ka10081, KRX 정규장 확정치)를 써라.**
`investor_after_close`의 `cur_prc`도 이제 KRX 기준이라 `candle_daily_*`와 일치하지만, 종가의
정본은 일봉이다. `investor_after_close_all`의 `cur_prc`·`flu_rt`를 종가로 쓰면 지수 항등식이
최대 1.1%p 어긋난다. `profile_*`(ka10001)과 `short_selling_*`(ka10014)도 KRX 정규장 기준이다.

## 3주체 항등식은 닫히지만 잔차가 남는다

`investor_after_close`는 12페이지 1,200행에서 끊긴다(상장 종목 전체가 아니다). 2026-09-04 실측:

```
개인 −4,360,236 + 외국인 +969,489 + 기관계 +1,833,431 + 기타법인 +1,586,536 = +29,220 (백만원)
기관 세부합(금융투자·보험·투신·기타금융·은행·연기금등·사모펀드·국가) = 1,833,445 vs 기관계 1,833,431 → 차 14
```

기관 세부합은 사실상 정확히 닫힌다. 3주체+기타법인 잔차 292억원(총거래의 0.7%)은 1,200행에서
잘린 소형주 몫이다. **잔차를 기타법인으로 역산하지 마라** — 기타법인은 이미 실측값으로 있고,
잔차는 절단 오차다. 리포트에는 잔차 규모를 각주로 밝히면 된다.

## 과거 사고가 구조적으로 막히는 지점

- **기타법인 잔차 역산 불필요** — `investor_after_close` 응답에 `etc_corp`가 직접 있다.
  프롬프트에 남아 있는 "3주체 합이 0으로 닫히지 않으면 잔차를 기타법인 몫으로 역산하라"는
  지시는 **무시하고** API 실측값을 그대로 써라.
- **삼성전자 우선주 누락 불가** — 보통주(005930)와 우선주(005935)를 처음부터 따로 받는다.
  2026-08-25에 우선주를 "확인 불가"로 두고 0%로 가정해 헤드라인이 92%→81%로 틀어진 사고가
  재발할 수 없다.
- **등락률 부호 오류 불가** — 키움 등락률에는 부호가 정확히 들어 있다.
  companiesmarketcap의 무부호 등락률이나 '마감' 제목을 단 장중 스냅샷 기사를 등락률
  소스로 쓸 이유가 이제 없다.

## 금융투자·사모펀드는 별도 계산

`ka10063`(=`investor_intraday_*`)에는 **금융투자와 사모펀드 코드가 없다.** 그 둘은
`investor_after_close`의 종목별 `fnnc_invt` / `samo_fund` 필드를 합산해서 구하라.

## 해외 지수는 ETF 대용이다 — 표기에 주의

`us_sp500_spy` 등은 지수 자체가 아니라 **추종 ETF의 종가**다. 키움 해외주식 API에
지수 시세가 없어서 쓰는 대용치이며, 배당락과 추적오차 때문에 지수 등락률과 소수점
단위로 어긋난다. 방향과 등락폭을 읽는 데는 충분하지만, 리포트에 **"S&P500 -0.39%"라고
단정해 쓰지 말고 "SPY -0.39%" 또는 "S&P500(SPY 기준) -0.39%"로 적어라.** 지수의 정확한
종가가 필요하면 그것만 웹으로 확인한다.

`us_gold_gld`·`us_wti_uso`·`us_ustreasury20y_tlt`·`us_dollar_uup`도 마찬가지로 각각
금·WTI·미 장기국채·달러인덱스의 **대용 ETF**다. 등락률은 쓰되 절대 수치(온스당 달러,
배럴당 달러, 금리 %)를 이 값에서 만들어내지 마라.

## ★웹으로 가기 전에 반드시 수집기에 먼저 물어라

2026-09-05 리허설에서 KODEX MSCI Korea(156080)와 EWY를 웹 검색으로만 찾다가 못 구해
"확인 불가"로 적은 사고가 났다. **둘 다 키움으로 정상 조회된다.** 아래를 기억하라.

- **국내 상장이면 6자리 코드로 무엇이든 조회된다.** ETF·ETN 포함. `ka10001`(현재가·시총·
  PER/PBR)과 `ka10081`(일봉)에 코드만 넣으면 된다. 156080은 `basket_kodex_msci_korea`로
  프리셋에 들어 있다.
- **미국 상장이면 티커로 조회된다.** `usa20590`에 `stex_tp`(NY/ND/NA)와 티커. EWY·SKM(SK텔레콤
  ADR)·KB(KB금융 ADR)는 `us_ewy_korea_etf` 등으로 프리셋에 들어 있고, 그 밖의 티커는
  `--call usa20590 --path /api/us/mrkcond --body '{"stex_tp":"NY","stk_cd":"<티커>","base_dt":"<날짜>"}'`로
  단건 조회하라. **거래소 코드가 틀리면 1903으로 떨어지니 NY→ND→NA 순으로 시도하라.**
- 2026-09-04 실측: EWY 웹 검색은 9/3 종가(180.56)를 9/4 값으로 잘못 물어왔고, 키움은
  188.87(+4.60%)로 정확했다. **웹과 어긋나면 키움이 옳다.**

"확인 불가"로 적기 전에 위 두 경로를 시도했는지 스스로 확인하라. 시도하지 않은 것을
확인 불가로 적는 것은 데이터 부재가 아니라 조사 태만이다.

## KODEX·KOSPI 연립으로 반도체/나머지를 분리하라

`basket_kodex_msci_korea_daily`와 `index_kospi`가 같은 세션·같은 통화라 FX·시차 교란이 0이다.
반도체 등락률 S, 나머지 R로 두면

```
[0.6574 0.3426][S]   [KODEX]      det = +0.143000
[0.5144 0.4856][R] = [KOSPI]
```

2026-09-04 실측 (KODEX +1.93%, KOSPI +1.64%): **S = +2.62%, R = +0.60%.**
관심종목 바텀업(반도체 3종 시총가중 +2.72%, 비반도체 +0.52%)과 각각 0.09%p·0.08%p 안에서
일치했다. 두 방법이 이 정도로 맞으면 지수 분해를 신뢰해도 된다.

EWY(`us_ewy_korea_etf`)는 세 번째 식이다. 원화 환산 후 `0.4428·S + 0.5572·R`과 비교하라.
2026-09-04: 이론 +1.49% vs 실제 원화환산 +3.84% → **프리미엄 +2.35%p.** EWY 세션은 한국
마감 이후에 열리므로 이 초과분이 곧 미 세션 재평가분이며, **다음 개장의 갭 신호다.**
계수(0.6574/0.5144/0.4428)는 리밸런싱으로 바뀌므로 주기적으로 실측 갱신하라.
