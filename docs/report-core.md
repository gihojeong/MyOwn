# report-core — 4개 리포트 회차의 공용 규격

작성 2026-10-10. 이 문서는 ★루틴 프롬프트에서 뺀 공용 내용★을 모아 둔 곳이다.
프롬프트가 길어져 입력창에서 앞부분이 잘려 저장되는 사고가 나서(2026-10-10 실측:
개장전 2,611자·주간 13,240자 유실) 중복을 여기로 내렸다.

## [C0] 지위와 선후관계

읽는 순서와 우선순위다. 위가 이긴다.

1. `report_scoreboard` 의 `[인프라]` 절 — ★환경 상태(자격증명·API·수집기)의 정본★. 매 회차가 갱신한다.
2. `docs/common-report-guide.md` — ★서술 방식·용어·부록·예측력 복기·시장을 보는 틀★의 정본.
3. ★이 문서★ — 환경 확정 사실 · 기계적 제약 · 리포트 형식 · 포트폴리오 챕터.
4. `docs/trigger-prompts/{premarket,close,weekly}.live-*.txt` — 회차별 수집 항목·해석 규율 전문.
   `docs/collection-contract.md` · `docs/kiwoom-report-playbook.md` — 수집·계산 규격.
5. 루틴 프롬프트 — 회차 식별 · 납기 · 위 문서로의 포인터만 담는다.

프롬프트와 이 문서가 어긋나면 이 문서가 이긴다. 이 문서와 장부 `[인프라]` 절이 어긋나면 장부가 이긴다.

  재시도 12회면 호출 한 건이 실패할 확률이 0.67^12 = 0.8% 다.
  조회 20회 연속 20/20 성공(35.3초)으로 검증했다. ★8050을 한 번 보고 멈추지 마라.★
- ★오류코드 판별표★

  | 8001 | 키 검증 실패 | ★키★ 문제 | 재발급 필요. 더미 키를 넣으면 이것이 온다 |
  | 8005 | 토큰 무효 | ★캐시★ 문제 | `rm -rf ~/.cache/kiwoom-collect` |
  | 8020 | 필수 파라미터 누락 | 호출 형식 | 요청 본문 점검 |

### [E3] 키움 WAF가 User-Agent 를 본다

- urllib 기본 UA 는 막힌다 — `HTTP 400 "Request Blocked"` (본문이 HTML) 로 온다.
  실측: UA 없음 · `Python-urllib/3.11` → 차단 / `kiwoom-collect/1.0` · `Mozilla/5.0` → 정상.
- 수집기는 UA 를 박아 두고 있어 문제없다. ★직접 호출하는 임시 스크립트에는 반드시 UA 를 넣어라.★
- ★실패를 보면 ★더미 키 대조군★을 같이 돌려라. 둘 다 실패하면 키가 아니라 ★내 호출 방식★이 원인이다.
  2026-10-10 에 네 가지 키 조합이 전부 400 이라 "키가 죽었다"로 오진했는데, 더미 키도 같이 400 이었다.★

## [S] 수집 절차

1. ★토큰 캐시를 먼저 비워라: `rm -rf ~/.cache/kiwoom-collect`★
   같은 APP_KEY 로 키움 MCP(kiwoom-exec)가 새 접근토큰을 발급하면 수집기가 캐시한 토큰이
   서버에서 무효화된다 → 전 항목이 `8005` 로 떨어진다.
   실측 사고: 이 때문에 1차 시도가 70건 중 6건으로 붕괴했다.
2. ★`--check` 를 신뢰하지 마라★ — 죽은 토큰에도 `token_issued=true` 를 보고한다.
3. ★회차 동안 `kiwoom_query`(MCP)를 호출하지 마라.★ 명세 조회용 kiwoom-spec 은 자격증명을 안 쓰므로 무관.
4. ★`--log` 인자는 수집기에 없다. 주면 실패한다 — 쓰지 마라(2026-10-06 실측).★
5. 호출 형식:
   ```
   python3 scripts/kiwoom_collect.py --preset {premarket|close} --date <YYYYMMDD> \
           --pause 0.25 --out kiwoom.json
   ```
   - 마감 회차는 ★포그라운드 + `timeout 540`★ 으로 띄워라. `nohup` 백그라운드가 "exit 0" 을 내고도
     산출물 없이 끝난 전례가 있다. 2~6분 걸린다.
   - 개장전 회차는 백그라운드로 띄우고 도는 동안 Drive 계보 읽기·메일함·웹 조사를 병렬로 하라.
6. ★결과 JSON(약 4.5MB)을 Read 도구로 열지 마라.★ python 으로 필요한 키만 뽑아라.

## [K] 계산·코딩 규율

- ★모든 수치는 스크립트로 계산한다. 암산·추정 보정 금지.★ 산식과 전제를 계산박스로 노출하라.
- 서브에이전트(Agent)를 쓰지 마라.
- 파이썬은 heredoc 대신 Write 로 `.py` 저장 후 `python3` 실행하라.
- ★한글을 `\uXXXX` 이스케이프로 적지 마라 — 글자가 깨진다.★
  2026-10-08 실측: 격차→곝차 · 휴장→효장 · 규칙→괜칙 · 직전→진전 · 보정→부정 · 양측→양쇽.
  리터럴로 적고 ★생성 후 grep 으로 확인하라.★
- ★문자열 포매팅은 `%` 대신 f-string 을 쓰라★ — `%%` 누출 오류가 구조적으로 사라진다.
  f-string 안에 삼중따옴표·백슬래시 금지.
- numpy 없음. `'{:+,}'.format()` 을 쓰라(`%+,d` 미지원).
- Bash 출력은 32KB 에서 잘린다. 전문 읽기는 `fold -s -w 2400` 후 Read 도구로.
- ★`git clone` 에 토큰을 URL 로 주입하지 마라★ — 분류기가 Credential Exploration 으로 차단한다.
- ★분모 문턱: 분모가 0 에 가까워지는 비율 지표는 계산하지 마라.★ 값이 폭주해 의미가 없다.

### [P0] 왜 지수 판단에 도움이 되는가

### [P3] 채점 — Brinson 분해. 항등식이 검산이 된다

지수 분해(`D = Σwᵢrᵢ`)는 나머지 블록을 역산하므로 합계 일치가 ★항진명제★다. 검산이 아니다.
Brinson 분해는 다르다 — 세 효과를 ★독립적으로★ 계산한 뒤 합이 액티브 수익과 맞아야 한다.
어긋나면 어딘가 틀렸다는 뜻이다. ★이것이 진짜 검산이다.★

```
액티브 수익  A = Σᵢ (w_mᵢ − w_bᵢ) · rᵢ
배분 효과    AL = Σ_s (W_m,s − W_b,s) · (r_b,s − r_B)
선택 효과    SE = Σ_s  W_b,s        · (r_m,s − r_b,s)
상호작용     IN = Σ_s (W_m,s − W_b,s) · (r_m,s − r_b,s)
★검산: AL + SE + IN − A = 0 (오차 1e-9 이내)★
```

`r_B` 는 BM 전체 수익률. `W` 는 섹터 집계 비중, `r_s` 는 섹터 내 가중 수익률.

누적 지표:
- 누적 액티브 수익 = Σ 일별 A (단순합. 복리는 주간 회차가 따로 낸다)
- ★정보비율 IR = mean(A) ÷ std(A) × √252★
  - ★표본이 20회 미만이면 IR 을 숫자로 적지 말고 "표본 부족(n=…)"으로 적어라.★
    std 가 작을 때 IR 이 폭주한다([K] 분모 문턱).
- 적중률 = A > 0 인 날 ÷ 전체 날
- 실현 추적오차 = `std(A) × √252`. 목표 3~5% 밴드 안에 있는지 적는다.
  - 20회 미만이면 교차단면 근사로 대체: `TE ≈ √(Σ_s (W_m,s − W_b,s)² · σ_s²) × √252`

### [P4] 리포트에 어떻게 싣는가

용량 때문에 ★50종목 표를 전부 인쇄하지 않는다.★

- 표 1 — ★오늘의 포지션★: 목표 베타 · 현물/현금/선물 비율 · 섹터 OW/UW 상위 3+3 ·
  종목 OW 5 / UW 5 (종목 · BM비중% · 모델비중% · 액티브%p · 한 줄 이유).
- 표 2 — ★어제 채점★: A · AL · SE · IN · 검산 0 · 누적 A · 적중률 · IR(또는 표본 부족) · TE.
- 계산박스 하나 — Brinson 항등식을 실제 수치로 전개.
- ★모순 점검 한 줄★: 지수 전망 E 의 부호와 반도체 섹터 액티브의 부호가 같은 방향인지,
  다르면 왜 다른지. 이것을 빠뜨리지 마라 — 이 장의 존재 이유다.
- 전체 50종목 비중은 Drive 기록에만 남긴다.
