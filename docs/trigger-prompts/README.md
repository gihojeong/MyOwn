# KOSPI 리포트 예약작업 프롬프트 백업

Routine(예약작업) 프롬프트는 트리거에만 저장되고 버전 관리가 되지 않는다.
키움 API 수집을 0순위 소스로 넣는 개정을 하면서, 되돌릴 수 있도록 개정 전후를 남긴다.

| 파일 | 트리거 | 스케줄(KST) |
| --- | --- | --- |
| `close.*.txt` | `trig_01LbQamCFtaT5ebZfn8wmgod` KOSPI 마감 리포트 | 평일 18:05 |
| `premarket.*.txt` | `trig_01EEvoe4TZ4FhgJK54iNKurd` KOSPI 개장 전 브리핑 | 평일 06:00 |
| `weekly.*.txt` | `trig_01NhobFHbi1FErXGQN9ewVZu` KOSPI 주간 리뷰 | 토 06:00 |

`.before.txt`는 2026-09-05 개정 직전 상태, `.after.txt`는 개정 후 적용된 내용이다.
되돌리려면 `.before.txt` 내용을 그대로 트리거 프롬프트로 다시 넣으면 된다.

`.after.txt`는 2026-09-05에 실제로 트리거에 적용된 내용과 바이트 단위로 일치함을
확인했다(적용 후 트리거를 다시 읽어 대조).

개정 내용은 세 파일 모두 동일한 형태이며, 기존 규칙 앞에 "0순위 데이터 소스 —
키움 OpenAPI 수집기" 절 약 1KB를 추가하고 진행 순서 한 줄을 고친 것이 전부다.

- 지침 본문은 프롬프트에 넣지 않고 `docs/kiwoom-report-playbook.md`를 가리킨다.
  세 프롬프트가 같은 두 페이지짜리 대응표를 각자 들고 있으면 수집 항목 하나를
  바꿀 때마다 셋을 다 고쳐야 하기 때문이다. 이제 수집기와 지침이 같은 커밋에서 바뀐다.
- 예약작업 세션에는 저장소가 붙지 않으므로(`folders: []`) 스크립트도 지침도
  raw.githubusercontent.com에서 받는다. 저장소가 public이라 인증 없이 받아진다.
- 진행 순서에 수집기를 백그라운드로 먼저 띄우는 단계를 넣고, 웹 조회를 "수집기가
  채우지 못한 항목만"으로 강등.
- `ka10066` 응답에 `etc_corp`가 직접 있으므로, 기존의 "3주체 잔차를 기타법인 몫으로
  역산하라"는 지시를 무시하라고 명시. 프롬프트 뒷부분의 그 문장 자체는 남겨뒀다 —
  지우면 diff가 커져 전사 사고 위험이 올라간다.

수집기에 없어서 웹 경로가 그대로 필요한 것: 선물·베이시스·미결제, 원/달러, 국고채,
공매도, 시가총액·상장주식수, 해외 증시.

**마감·주간 트리거는 고치지 않는다.** 아래 「마감 리포트는 고치지 않았다」 참조.

### 왜 필요한가

개장 전 브리핑의 휴장 게이트(21~23행)가 **플레이북을 받아 읽는 지점(72행)보다 앞에 있다.**
그래서 한국 증시 휴장일에는 `즉시 종료`로 빠져나가고, **플레이북에 무엇을 써도 실행되지 않는다.**
결과적으로 **연휴 동안의 미 정규장이 아무 데도 기록되지 않는다.**

2026 추석이 실례다. 국장이 9/24~9/27 쉬는 사이 미 정규장은 **3회(9/23·24·25)** 돌아가는데,
현행 게이트로는 9/24·9/25 두 회차가 아무것도 남기지 않고 종료한다. 그러면 9/28 아침 06:00이
07:30 마감 안에 3회분을 맨손으로 복원해야 한다.

하필 여기가 제일 약하다. 2026-09-23 정확도 감사에서 **갭 예측이 최악 지표**로 나왔다 —
평균 오차 **+0.7456%p**, 최근 5거래일 **+1.0231%p에 부호 5/5 동일**. 누적 미 세션이 많을수록
커지는 오차인데 정작 모아두는 곳이 없었다.

### 무엇이 바뀌었나

**게이트 한 문단(3줄 → 20줄)만 바뀐다. 나머지는 한 글자도 같다.**
`mkprompt.py` 가 `premarket.after.txt` 를 읽어 그 문단만 치환하고,
치환분을 되돌리면 원본과 완전히 일치하는지 assert 로 검증했다(원본 19,351자 → 20,279자).

바뀐 동작: 평일인데 한국 증시만 휴장이면 **리포트·메일은 그대로 생략하되**, 종료 전에
간밤 미 세션 한 줄을 Drive `kospi_overseas_gap_log` 에 적는다(2분 이내).
**토·일은 예외** — 토요일은 주간 리뷰가 같은 시각에 그 주 미 세션을 담당하고,
일요일은 간밤 미 세션 자체가 없다.

### 편집 경로 (앱 UI)

Claude **데스크톱 앱** 좌측 사이드바 `예약됨` 에 네 루틴이 있다. 브라우저
`claude.ai/code/routines` 에는 이 루틴들이 뜨지 않는다 — 거기엔 옛 테스트용만 남아 있다.
실행 결과 대화 상단의 `˅` 메뉴는 **대화 메뉴**라 프롬프트 편집이 없다(스킬로 전환·세션 ID
복사·고정·이름 변경·프로젝트에 추가·보관·삭제). 루틴 본체로 가는 항목은 **`예약된 작업 보기`** 다.

### 마감·주간 트리거는 고치지 않는다 (2026-09-23 실측)

세 프롬프트에서 플레이북 수신 지점과 게이트 위치를 실제로 재 봤다.

| 트리거 | 플레이북 수신 | 게이트 | 판정 |
| --- | --- | --- | --- |
| `premarket.after.txt` | 72행 | 휴장 종료 21행 | 게이트가 먼저 → 고쳤다 |
| `close.after.txt` | **23행** | 휴장 종료 63행 | **수신이 먼저** |
| `weekly.after.txt` | 80행 | 24행 "토요일이 아니면 종료" | **요일 가드**이지 휴장 게이트가 아니다 |

- **마감**: 휴장일에도 플레이북을 읽고 나서 종료하므로 거기 쓴 규칙이 닿는다. 게다가 18:05는
  미 정규장 개장(22:30) 전이라 그 시점에 적을 간밤 세션이 없다. **두 가지 이유로 제외.**
  (초판에 "마감도 같은 구조의 게이트"라고 적었던 것은 틀렸다. 수신이 게이트보다 앞선다.)
- **주간**: 토요일엔 게이트를 그냥 통과하고 80행에서 플레이북을 받는다. 손댈 것이 없다.

**예측 정확도 규율·전문용어 금지·누적 장부 의무는 셋 다 플레이북 경유로 이미 걸려 있다.**
트리거를 고쳐야 하는 경우는 오직 **게이트가 수신보다 앞서는 구조** 하나뿐이었다.

### 남은 확인 — 주간 리뷰 첫 실행(2026-09-26 06:00)

`weekly.after.txt` 150~172행에 **자체 채점 블록**이 있다. 169행 "계통 편향 진단"은
이미 있던 지시인데도 한 주 안의 5개 점만 보느라 6거래일 편향을 놓친 바로 그 문장이다.
이제 플레이북이 `fa.py --window weekly` 누적 롤업을 추가로 요구한다. **둘이 경합해
자체 채점만 하고 누적 롤업을 건너뛸 위험**이 있다. 9/26 산출물에 주 단위 롤업(W38 vs W39
비교)이 실제로 들어갔는지 확인하고, 빠졌으면 그때 `weekly` 트리거에 한 줄을 넣는다.

## 2026-09-24 — 수집 경로 통일

세 회차(`premarket` / `close` / `weekly`)의 프롬프트에서 데이터 수집 절을 잘라내고
**동일한 블록** 하나로 바꿨다. 결과 파일은 `*.unified-20260924.txt` 세 개다.

세 블록의 차이는 **정확히 두 줄**이다 — 프리셋 이름과 기준일, 그리고 항목 수.

```
close     : --preset close     --date <오늘 YYYYMMDD>                       (90항목)
premarket : --preset premarket --date <0단계에서 확정한 직전 거래일>         (81항목)
weekly    : --preset weekly    --date <지난주 금요일 YYYYMMDD>               (70항목)
```

수집 방식이 바뀌면 프롬프트 세 개가 아니라 `docs/collection-contract.md` 하나를 고친다.
프롬프트는 그 문서를 `curl`로 읽어 그대로 따르고, 충돌하면 문서가 이긴다.

이번에 함께 바로잡은 것:

- 세 프롬프트에 공통으로 남아 있던 "선물·베이시스·미결제·원/달러·국고채·공매도·
  시가총액·상장주식수·해외 지표는 웹으로 조사하라"는 지시를 **폐기**했다.
  그 항목들은 2026-09-05~09-24 사이에 전부 API로 들어왔다.
- 종가는 KRX 확정치, 키움 `cur_prc`는 NXT 포함이라 정규장 종가가 아니라는 규칙을 명시.
- 실패 유형을 다섯 가지로 분리(미등록 / 미신청 / 미게시 / 이그레스 403 / 모의투자 미제공).
- 수집기 기동 전 5초 게이트(`env | grep -c '^APP_'` + `--check`)를 절차에 못박았다.

## Code 루틴으로 옮길 때

`create_trigger` MCP 도구로 만든 루틴은 **커넥터(Drive·Gmail)도 저장소도 붙지 않는다**
(2026-09-24 실측: `connectors` 파라미터가 조직 정책으로 차단, 생성된 루틴의
`mcp_connections`와 `config.sources`가 모두 비어 있음). 따라서 세 루틴은
claude.ai/code의 루틴 UI에서 사람이 직접 만들어야 하고, 프롬프트 본문으로
위 `*.unified-20260924.txt` 파일을 그대로 붙여 넣으면 된다.

| 루틴 | cron (UTC) | KST |
| --- | --- | --- |
| 개장 전 브리핑 | `0 21 * * 0-4` | 평일 06:00 |
| 마감 리포트 | `5 9 * * 1-5` | 평일 18:05 |
| 주간 리뷰 | `0 21 * * 5` | 토 06:00 |

모델은 Opus로 지정한다(지정하지 않으면 Sonnet으로 발화된다 — 2026-09-24 실측).
