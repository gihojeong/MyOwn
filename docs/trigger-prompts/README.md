# KOSPI 리포트 예약작업 프롬프트 백업

Routine(예약작업) 프롬프트는 트리거에만 저장되고 버전 관리가 되지 않는다.
키움 API 수집을 0순위 소스로 넣는 개정을 하면서, 되돌릴 수 있도록 개정 전후를 남긴다.

| 파일 | 트리거 | 스케줄(KST) |
| --- | --- | --- |
| `close.*.txt` | `trig_01LbQamCFtaT5ebZfn8wmgod` KOSPI 마감 리포트 | 평일 18:05 |
| `premarket.*.txt` | `trig_01EEvoe4TZ4FhgJK54iNKurd` KOSPI 개장 전 브리핑 | 평일 06:00 |
| `weekly.*.txt` | `trig_01NhobFHbi1FErXGQN9ewVZu` KOSPI 주간 리뷰 | 토 06:00 |

`.before.txt`는 2026-09-05 개정 직전 상태, `.after.txt`는 개정 후 적용된 내용이다.
되돌리려면 `.before.txt` 내용을 그대로 트리거 프롬프트로 다시 넣으면 된다.

`.after.txt`는 2026-09-05에 실제로 트리거에 적용된 내용과 바이트 단위로 일치함을
확인했다(적용 후 트리거를 다시 읽어 대조).

개정 내용은 세 파일 모두 동일한 형태이며, 기존 규칙 앞에 "0순위 데이터 소스 —
키움 OpenAPI 수집기" 절 약 1KB를 추가하고 진행 순서 한 줄을 고친 것이 전부다.

- 지침 본문은 프롬프트에 넣지 않고 `docs/kiwoom-report-playbook.md`를 가리킨다.
  세 프롬프트가 같은 두 페이지짜리 대응표를 각자 들고 있으면 수집 항목 하나를
  바꿀 때마다 셋을 다 고쳐야 하기 때문이다. 이제 수집기와 지침이 같은 커밋에서 바뀐다.
- 예약작업 세션에는 저장소가 붙지 않으므로(`folders: []`) 스크립트도 지침도
  raw.githubusercontent.com에서 받는다. 저장소가 public이라 인증 없이 받아진다.
- 진행 순서에 수집기를 백그라운드로 먼저 띄우는 단계를 넣고, 웹 조회를 "수집기가
  채우지 못한 항목만"으로 강등.
- `ka10066` 응답에 `etc_corp`가 직접 있으므로, 기존의 "3주체 잔차를 기타법인 몫으로
  역산하라"는 지시를 무시하라고 명시. 프롬프트 뒷부분의 그 문장 자체는 남겨뒀다 —
  지우면 diff가 커져 전사 사고 위험이 올라간다.

수집기에 없어서 웹 경로가 그대로 필요한 것: 선물·베이시스·미결제, 원/달러, 국고채,
공매도, 시가총액·상장주식수, 해외 증시.

## ★적용 대기 중 — `premarket.gapfix-20260923.txt` (2026-09-23)

**아직 트리거에 넣지 않았다. 사용자가 붙여넣어야 적용된다.**

### 왜 필요한가

개장 전 브리핑의 휴장 게이트(21~23행)가 **플레이북을 받아 읽는 지점(72행)보다 앞에 있다.**
그래서 한국 증시 휴장일에는 `즉시 종료`로 빠져나가고, **플레이북에 무엇을 써도 실행되지 않는다.**
결과적으로 **연휴 동안의 미 정규장이 아무 데도 기록되지 않는다.**

2026 추석이 실례다. 국장이 9/24~9/27 쉬는 사이 미 정규장은 **3회(9/23·24·25)** 돌아가는데,
현행 게이트로는 9/24·9/25 두 회차가 아무것도 남기지 않고 종료한다. 그러면 9/28 아침 06:00이
07:30 마감 안에 3회분을 맨손으로 복원해야 한다.

하필 여기가 제일 약하다. 2026-09-23 정확도 감사에서 **갭 예측이 최악 지표**로 나왔다 —
평균 오차 **+0.7456%p**, 최근 5거래일 **+1.0231%p에 부호 5/5 동일**. 누적 미 세션이 많을수록
커지는 오차인데 정작 모아두는 곳이 없었다.

### 무엇이 바뀌었나

**게이트 한 문단(3줄 → 20줄)만 바뀐다. 나머지는 한 글자도 같다.**
`mkprompt.py` 가 `premarket.after.txt` 를 읽어 그 문단만 치환하고,
치환분을 되돌리면 원본과 완전히 일치하는지 assert 로 검증했다(원본 19,351자 → 20,279자).

바뀐 동작: 평일인데 한국 증시만 휴장이면 **리포트·메일은 그대로 생략하되**, 종료 전에
간밤 미 세션 한 줄을 Drive `kospi_overseas_gap_log` 에 적는다(2분 이내).
**토·일은 예외** — 토요일은 주간 리뷰가 같은 시각에 그 주 미 세션을 담당하고,
일요일은 간밤 미 세션 자체가 없다.

### 적용 방법

`premarket.gapfix-20260923.txt` **전문**을 `trig_01EEvoe4TZ4FhgJK54iNKurd`
(KOSPI 개장 전 브리핑) 프롬프트에 통째로 붙여넣는다. 되돌리려면 `premarket.after.txt` 로 복귀.

### 마감 리포트는 고치지 않았다

`trig_01LbQamCFtaT5ebZfn8wmgod` 도 같은 구조의 게이트를 갖고 있으나, 18:05는 미 정규장
개장(22:30) 전이라 그 시점에 기록할 간밤 세션이 없다. **개장 전 것만 고치면 충분하다.**

### 적용 전까지의 임시 대응

토요일 주간 리뷰가 그 주 휴장 구간의 미 세션을 대신 담는다(플레이북에 규정했고, 주간 리뷰는
휴장 게이트가 없어 정상 기동한다). **연휴에 토요일이 끼지 않으면 그마저 없으므로**, 그때는
휴장 직후 첫 개장일이 직접 복원하고 실패 시 "미 세션 N회 미반영"을 **'영향 있음'으로** 적는다.
