# 마감 리포트 생성 파이프라인 (2026-09-18 회차 기준)

저녁 마감 리포트를 만드는 데 실제로 쓴 스크립트다. 종가·비중 같은 **당일 값이 상단에 하드코딩**돼 있으므로
그대로 재실행하는 용도가 아니라, **다음 회차가 읽고 값만 갈아끼우는 참조 구현**이다.

실행 순서:

| 파일 | 하는 일 | 산출 |
| --- | --- | --- |
| `calc.py` | 시총 상위 31 분해, 항등식 검증, 5블록·클러스터 집계, 집중도 | `calc_out.json` |
| `score.py` | 예측 대비 괴리 채점(오차 귀속), 다음 거래일 시나리오·sigma | `fc.json` |
| `build.py` | 이메일 호환 HTML 생성(테이블 + 인라인 style만) | `kospi_close_<날짜>.html` |
| `verify.py` | 발송 전 자동 검증 | 통과/실패 |
| `drive.py` | Drive 기록용 상위 31 비중 스냅샷 출력 | stdout |

산출물(`calc_out.json` · `fc.json` · `kospi_close_*.html`)과 수집기 원자료는 `.gitignore`에 있다.

## 이 회차에서 고친 버그 — 재발 방지용

1. **`card()`가 `bdir()`/`bstr()`를 호출하지 않아** 방향·강도 배지가 리터럴 `up` / `최상`으로 출력됐다(6장 전부).
   `verify.py`의 부호-기호 검사는 배지에 숫자가 없어 이것을 잡지 못한다.
2. **`% 포맷을 거치지 않은 문자열의 리터럴 `%%`가 본문에 그대로 샜다**(mono 5개 블록).
   `mono('...86.7%%...')`처럼 `% (...)`를 적용하지 않은 호출은 `%%`가 치환되지 않는다.
   → 모든 헬퍼(`sec`/`para`/`box`/`mono`/`tbl`)에 `pc(t) = t.replace("%%", "%")` 안전망을 넣었고,
   `verify.py`에 `h.count("%%") == 0` 검사 `[3b]`를 신설했다. 4회 연속 재발하던 문제가 이걸로 닫힌다.
3. **카드가 전일 수치를 18:0x 스냅샷값으로 인용**해 본문 표의 확정치와 어긋났다.
   전일 값은 반드시 아침 회차가 확정한 값을 쓴다.

## 손계산 금지

NXT 시총가중 괴리 5개 값을 초안에서 손계산했다가 전부 틀렸다:

```
시총가중 -0.25617 -> -0.28752      지수기여 -0.15503 -> -0.17410
반도체3종 -0.29827 -> -0.33265     비반도체5종 +0.27813 -> +0.00598
```

특히 비반도체 5종은 부호가 섞여 직관이 크게 빗나간다. **시총가중 평균은 예외 없이 스크립트로 계산한다.**

## 수집기 관련

- 저녁 회차에는 키움 가격 계열이 전부 NXT 애프터마켓가로 오염된다.
  **종가는 `markets.hankyung.com/stock/<코드>`, 전일종가 검증은 `profile_*.base_pric`.**
- `ka10066`(`investor_after_close`)의 금액 컬럼은 저녁 회차에서 하루 지연된다.
  시장 합계는 `ka10051`을 **`/api/dostk/sect`** 경로로 단건 호출해 받는다(`/api/dostk/stkinfo`는 실패):

  ```bash
  python3 scripts/kiwoom_collect.py --call ka10051 --path /api/dostk/sect \
    --body '{"mrkt_tp":"0","amt_qty_tp":"0","base_dt":"<YYYYMMDD>","stex_tp":"1"}' --out ka10051.json
  ```

  응답 `inds_netprps[0]`(`inds_cd=001`)에 5주체 + 기관 7개 세부가 있고 합이 정확히 닫힌다.
- **`ps aux | grep -c "[k]iwoom_collect.py"`는 자기 자신의 래퍼를 세어 항상 1을 반환한다.**
  완료 판정은 `ls -la kiwoom.json`과 로그 파일로 한다.
